# Frontend: Boston outbreak cascade

A SvelteKit site over the model in `seir/`. A thin FastAPI app (`api/`) runs
the model; the site (`web/`) draws it. Minimal dark theme, no account, no
database.

## Run it

Python 3.11+ and Node 20+. From the repository root:

```bash
# once
pip install -r seir/requirements.txt -r frontend/api/requirements.txt
npm --prefix frontend/web install

# terminal 1: the model API on :8000
uvicorn main:app --app-dir frontend/api --port 8000

# terminal 2: the site on :5173 (proxies /api to :8000)
npm --prefix frontend/web run dev
```

Open http://localhost:5173.

For a demo from one process, build the site once; the API then serves it too:

```bash
npm --prefix frontend/web run build
uvicorn main:app --app-dir frontend/api --port 8000      # open http://localhost:8000
```

The map basemap (CARTO dark tiles) needs internet and, to drop CARTO's "API key
required" watermark, a free key from https://carto.com/basemaps/apikey/ in
`frontend/web/.env` (see `.env.example`; git ignores `.env`). The key is read at
build time, so rebuild after setting it. Offline, the map still draws
neighborhoods, hospitals and flows on a plain dark background.

## Pages

| page | what it shows |
|---|---|
| Map | Boston neighborhoods coloured by infectious share, ever infected, hospitalised or access lost; hospitals by bed occupancy and diversion; usual patient flows; day-by-day playback |
| Epidemic | R₀, Rₑff, generation and doubling time; transmission, incubation and recovery rates (given and realised); force of infection; S, E, I, R, ward, ICU, admissions; neighborhood heatmap; by age |
| Hospitals | occupancy heatmap with diversion days; per-hospital occupancy and FDNA operability; the FDNA dependency graph on any day; who loses access; rerouting; criticality ranking with one-click knockouts |
| Uncertainty | stochastic ensemble with 5–95% and 25–75% bands, take-off share and peak distribution; one-at-a-time sensitivity tornado with elasticities |
| Validation | Omicron fit and winter 2020–21 out-of-sample checks against HHS and CTP data, with pass bars and a naive baseline; sliders to try to break the fit |
| Model | the daily loop, equations, the current scenario's parameters, assumptions and sources |

The controls panel (right) changes the pathogen preset, R₀, latent and
infectious periods, severity, lengths of stay, prior immunity, seed size and
run length, plus the hospital system (diversion threshold, hospitals that stay
open, distance decay, staff absence, ICU strain) and FDNA disruptions (cap a
node for a window of days). Every change re-runs the model, usually in under
half a second. Space plays the timeline; arrow keys step a day (shift: a week).

## API

`api/main.py`, all JSON. Changes are dotted paths, as with the CLI's `--set`.

| endpoint | does |
|---|---|
| `GET /api/scenarios`, `GET /api/scenario/{id}` | scenario list; one scenario's config, derived rates and map places |
| `GET /api/presets` | disease presets and their sources |
| `POST /api/run` | `{scenario, epi, system, events}` → SEIR curves, rates, by-neighborhood and by-age series, and for system scenarios hospital load, operability, diversion, access |
| `POST /api/ensemble` | `+ {runs, seed}` → quantile bands, sample runs, peaks, take-off share |
| `POST /api/sensitivity` | `+ {params, metric, rel}` → one-at-a-time table |
| `POST /api/criticality` | `+ {level}` → FDNA nodes ranked by extra weighted access loss |
| `POST /api/validation` | `{omicron, winter}` changes → model, observed and naive series with scores |

`pytest frontend/api` runs the API's smoke tests.

## Where the model pieces come from

- `seir/cascade/epi`: the SEIR layer, unchanged.
- `seir/cascade/{allocation,network,fdna,reroute,equity,recorder,scenario,api,contracts}.py`:
  the cascade reference's system layer, copied unchanged, with its tests in
  `seir/tests/test_system.py` (scenarios in `seir/systems/`).
- `seir/systems/boston_city.yaml`: a 15-neighborhood, 7-hospital Boston scenario
  generated by `seir/systems/make_boston.py` from two CSV tables. Populations,
  coordinates, the Boston share of beds, travel times and vulnerability weights
  are approximate and labelled as assumptions on the Model page.
